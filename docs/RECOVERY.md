# Stopping, restoration and removal

## Normal shutdown

For Mac local tests, use `python3 scripts/lab.py stop`. It handles only desktop apps generated by this checkout and the verified dedicated AVD on `emulator-5580`. It does not run `killall java`, stop the ADB server, or act on other devices.

For a wireless experiment, press Ctrl-C in its terminal. The supervisor stops its JVM/relay and closes private IPC; the native process restores Wi-Fi after receiving EOF/cancellation. Inspect that run's `runs/<run>/result.json`: **check `native_complete`, `wifi_restored` and `recovery_required` together**. An exit code or Wi-Fi icon alone is insufficient.

## Wi-Fi journal

Path: `bridge/wireless-session/runtime/wifi-recovery.json`.

It records original Wi-Fi power, SSID/BSSID, target identity, interface and schema version, but no password. It is written before association, inside a 0700 directory with 0600 file permissions. A journal is an outstanding verification/restoration obligation, not disposable cache that can be deleted to bypass a check.

If Wi-Fi was originally off, it is turned off again only when the current association is still our target or is disconnected. If it was originally connected, the tool first verifies ownership of the current target before disconnecting and waiting for macOS to rejoin the saved original network. It does not guess passwords, rewrite global network service order, or disconnect a different network the user selected afterward.

If `wifi_restored=false` or the journal still exists:

1. Preserve the journal, native receipt and run result. Do not delete files, rewrite state, or change unverified fields to true.
2. Check whether the native background worker is still running. A blocked system Wi-Fi call may still hold `radio.lock`; do not start a competing mutation.
3. After the system call returns or the native process exits, manually run:

   ```sh
   ./bridge/wireless-session/recover-wifi.command
   ```

4. Recovery handles only the existing record. It does not open Bluetooth, start the emulator, or connect to the car's TCP endpoint.
5. If the original network needs a password, does not auto-join, has a changed BSSID, or the user selected another network, the user may need to restore the original state in System Settings before rerunning verification. Retain an incomplete result until completion is established.

A driver/system-blocked CoreWLAN call cannot be guaranteed to restore within a fixed time. The supervisor does not kill a native worker that may still be responsible for restoration and then claim success. Locks prevent competing changes; they cannot force a system call to finish.

## APK restoration

This applies only to the dedicated emulator. The original official APK is hash-pinned in `dependencies.lock.json` and retained at `.cache/downloads/aare-1.1.1.apk`. The local patched APK uses a different signer; `adb install -r` cannot switch between those signatures.

To return to the official APK, preserve needed settings and confirm that resetting AARE app data is acceptable, then explicitly target the dedicated AVD:

```sh
adb -s emulator-5580 emu avd name
# The result must be AARE_Mac_API35. Otherwise, stop.
adb -s emulator-5580 uninstall net.prototux.aare
adb -s emulator-5580 install .cache/downloads/aare-1.1.1.apk
```

The official APK may reproduce the black-screen issue with the same emulator encoder. Restoring the original signature does not resolve that compatibility issue. Do not apply these steps to a head unit or another phone.

## Source rollback

This is an independent integration project; it does not overwrite the original upstream checkout or vehicle candidate builds. To roll back, first finish active sessions and any journaled network restoration, then return to a known-good Git commit and rebuild. Generated classpaths and app-images must be regenerated for the current path.

Do not remove the native app or runtime before resolving an outstanding journal: that removes the recovery tool and evidence while the obligation remains.

## Removal

Stop your own local and wireless sessions and verify that no recovery journal remains outstanding. If the dedicated `AARE_Mac_API35` AVD is no longer needed, the user can delete it in Android Device Manager. It contains emulator data; deleting it is not lossless cache cleanup.

Afterward, this checkout's `.cache`, `build`, `bridge/core` and generated `build/apps/runtime/evidence/runs` folders can be removed. The Android SDK, JDK, ffmpeg and Gradle cache may be shared with other projects and are **outside automatic removal scope**. Retain or remove historical run files containing network identifiers or media data according to the user's wishes.
